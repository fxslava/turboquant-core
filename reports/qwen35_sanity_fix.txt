Qwen3.5 2K sanity failure: source diagnosis and synchronization

The first two preflight calls are page=128, batch=1, context=2048, splits=1 and 2.
kBlocks is {128,1024}, but the split loop runs before the next batch or page size.
The user supplied these physical Ascend950PR_9579 results:
  split 1: relative_l2=0.00138769, max_abs=0.00751397
  split 2: relative_l2=0.317554, max_abs=1.16969
  host-merged partials versus golden: relative_l2=0.317527
  device result versus host-merged partials: relative_l2=0.00113101
Only heads 3..5 have substantially incorrect merged partials. This identifies
corrupted attention partials, rather than inaccurate arithmetic in the final merge.

Packing and descriptor audit
----------------------------
The benchmark writes the same NzTiledPackedByte and NzTiledScaleIndex contract
used by tq_test helpers. For one KV head, each scale row is 8 floats (32 bytes):
K is lane 0 and V lane 1. The table reverses physical page IDs and is shared by
the descriptor builder and FP64 golden reference. Global slot is physical_page *
block_size + row_in_page. A packed K or V page is block_size * 128 bytes, and its
scale plane is block_size * 8 floats: 16,384/131,072 packed bytes and 1,024/8,192
scale floats for page sizes 128/1024 respectively. D does not bound page size.
The 64-row tile cursor uses shift=log2(block_size)-6 (1 or 4), and host splits
partition whole pages. At 2K and split=2 this yields 8+8 pages or 1+1 pages,
16 tiles per split in either case. All 32 tiles are visited exactly once. The
online-softmax state and output channel loops operate on 64 rows and 256
channels separately; the alias occurs when publishing their statistics tail.
Root cause
----------
BeginArgmaxProbe creates the fixed position-publication predicate (only lane 1)
at kProbePred, offset 392 floats in queryInBuf_. The online argmax fold was also
given arena[kProbePred] as its temporary predicate. Its comparisons replace the
fixed mask with equality/improvement masks, with eight repeated bits per head.
StagePartials then uses that overwritten mask in Select over the 16-float tail.
An improvement in the first head can overwrite lane 0 (the partial maximum);
an improvement in the second can overwrite lane 8 (the softmax mass). Argmax
positions are substituted into the statistics that Split-K reduction consumes.
The fused split=1 path normalizes its output before publishing the telemetry
record, so its numerical output can pass despite the same bad publication mask.

Fix
---
Give argmax comparisons a separate aligned 32-byte predicate at offset 536.
Keep position and page publication predicates at offsets 392 and 400. The arena
now spans 544 floats, still inside the existing 8192-byte query staging buffer.
No GM layout, tiling stride, head partition, kernel argument, UB allocation or
numerical tolerance was relaxed. The golden threshold remains relative_l2 < 0.01.
The predicate offsets are shared with a host regression that exercises all eight
three-head improvement masks and checks that max/sum lanes remain unchanged.
An independent host counterexample evaluates the actual 2K fixture's attention
partials and last-tile improvement masks. Applying the old alias gives head means
1.426866, 0.751270, 1.064988 for heads 3..5, and relative L2 0.317362321.
Keeping the publication mask intact gives relative L2 2.22809739e-15. This
reproduces the physical failure's pattern without modeling FP8 rounding or running
2K on a simulator. test_qwen35_telemetry retains both controls as a regression.

Synchronization with C:/vllm-ascend
---------------------------------
That checkout has already removed the inline attention telemetry from its vector
service and softmax leaf, so this particular predicate alias is absent there.
Its separate telemetry system is preserved; the inline probe is not reintroduced.
Its unused Split-K B-fractal zero-fill fix is imported into turboquant-core.
The executable tokens of turboquant_gemm_reduce.hpp and the Cube reducer service
match after ignoring comments, whitespace and repository-specific include paths.
The shared decode_launch_split helper and dense-padding/launch-coverage host
regression are also imported. Both repositories have the same additional layout
regressions for 16x128 and 2x1024 pages with one KV head and D=256.
The matching vLLM layout regressions are committed as c36faa24c. Existing unrelated changes in that checkout are left in place.

Verification and execution policy
---------------------------------
Host tests pass for physical tile coverage of all 64 launch configurations, both
2K page sizes, telemetry predicate lifetime, dense poisoned padding, dispatch,
and layout bijections. The 2K host golden difference between page sizes is
2.20e-15 (batch 1) and 2.34e-15 (batch 2) relative L2.
The four vLLM host contract gates pass with external pytest plugins disabled.
The standalone telemetry_dump and golden_decode_oracle tests also fail on the
unchanged committed baseline; those existing failures are not attributed to this
patch. Their baseline output is retained under build-qwen35-fix/baseline-head/.

CAModel is restricted to one 64-token page at split=1, two 64-token pages at
split=2, and a synthetic partial-reduction canary. No 2K CAModel result is claimed.
The simulator benchmark target rejects --verify and --run before ACL startup.
Use --canary --device 0, optionally --split-k 1 or --split-k 2.
Before this fix, isolated reduction arithmetic passed at relative L2 0 (split 1)
and 0.00173810671 (split 2), including the shared-pool offset control. These are
reducer controls, not post-fix full-decode verification.

Post-fix synthetic CAModel kernels completed and downloaded all six heads:
  split 1: relative_l2=0, max_abs=0
  split 2: relative_l2=0.00173810671, max_abs=0.00376403572
Both used D=256, three reduction rows per block, the production reducer, the
attention L1 prefix and the same 43,200-byte UB prefix/shared transient pool.
The simulator joined its threads after the host parity check, but its teardown
exceeded the 180-second process budget. These are completed kernel parity
checks, not clean process-exit passes. No 2K simulation was used for this check.
Evidence: build-qwen35-fix/reduce-fixed-s1/result.log and reduce-fixed-s2/result.log.
The retained runner accepts exactly one split (1 or 2) per process.

Post-fix full SIM and NPU builds completed successfully with CANN 9.2.0-beta.2,
C++17, -Wall -Wextra -Werror, the Cube reducer, and telemetry enabled. These
completed builds used the repository default SOC_VERSION=Ascend950PR_9599 and
dav-c310 ISA. An explicit Ascend950PR_9579 NPU build is recorded separately below.
The 64-token split-1 and 128-token split-2 full-decode attempts each reached their
120-second budget before golden output, so full-decode SIM parity is unverified.
Their exit code is 124; logs are in build-qwen35-fix/decode-fixed-s1/ and
build-qwen35-fix/decode-fixed-s2/. No further simulator execution is planned.
The SIM executable's --verify refusal and its 64-row static matrix were checked. Physical 2K parity must be checked on the 950PR after rebuilding the
kernel library as well as the executable; an old library retains the bug.
